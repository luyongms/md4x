# v0.2.5 — Scroll-sync module

**Status:** spec.
**Layer:** GUI shell. New module
`crates/md4x-gui/frontend/scroll-sync.js`. Subsumes (folds in) the
existing `frontend/alignment-math.js`. Trims state and helpers in
`app.js` and `alignment-ticks.js` accordingly.

---

## 1. Problem

Scroll synchronisation is the single most fragile part of the v0.2.x
GUI. The current implementation has accreted into:

- 4 sync entry points (editor scroll, editor cursor, preview scroll,
  preview click) implemented as separate functions in `app.js`.
- 5 module-level state variables (`previewExpected`, `editorExpected`,
  `previewLockUntil`, `editorLockUntil`, `_syncSuspendedUntil`)
  tracking bounce-back and lockout windows.
- A driver-state machine that lives in a *different* file
  (`alignment-ticks.js`) and learns "who is driving" from `wheel` and
  `touchmove` events.
- An `rAF` coalescer keyed by 3 magic strings (`editorScroll`,
  `editorCursor`, `preview`).
- A block-cache with manually-scheduled invalidations across
  `applyRender`, `switchTemplate`, and 250 ms / 1000 ms timeouts that
  exist to catch async KaTeX/mermaid layout finishes.
- Sync is fire-and-forget: target Y is computed once and dispatched;
  there is no closed loop to correct the residual line-interpolation
  drift that the user sees as ~1–6 px tick misalignment near
  cover-page seams.

Every new fix risks regressing another path because the contract
between these pieces is implicit and distributed.

## 2. Goal

Replace the scattered sync logic with **one coordinator module** that
owns:

1. The full state machine (driver detection, programmatic-write
   bounce-back suppression, suspension during splitter drag and
   render).
2. The resolver (line-level pinpoint sync — preview line ↔ editor
   line — with a closed-loop correction step that aligns red ticks
   except at end-of-doc).
3. The pure math primitives currently in `alignment-math.js`.

Existing UI surfaces (`alignment-ticks.js`, the iframe click handler,
the editor scroll listener, the CodeMirror update listener) become
thin adapters that **dispatch inputs** to the module and **read
outputs** from it. They no longer carry sync state.

Bidirectional contract:

- **Editor cursor moves** → preview scrolls so the cursor's source
  line lands at the same viewport-Y as the cursor; red tick on both
  strips lines up at that Y.
- **Preview clicks** → CodeMirror cursor jumps to the source line under
  the click; preview re-anchors on that line.
- **Either pane is scrolled** → the other follows so the *line at the
  driver's viewport-Y* lands at the same viewport-Y in the follower.
- **Force-align** runs **once** per resolver step: if the follower's
  measured tick Y differs from the resolver's expected tick Y by
  1 ≤ |Δ| ≤ 8 px after layout settles, the module emits a corrective
  `scrollBy(0, Δ)` on the follower. Larger deltas indicate a layout
  race — skipped, next driver event will re-resolve. End-of-doc is
  exempt: when the follower is already at `scrollHeight - clientHeight`
  the corrective scroll is suppressed.

## 3. Scope

**In scope.**

- New module `frontend/scroll-sync.js` (the coordinator).
- Folding `alignment-math.js` into the new module
  (re-exports kept for the test file that already targets it).
- A test file `frontend/tests/scroll-sync.test.mjs` that runs the
  state machine against a table of `(state, input) → (state, outputs)`
  cases. Pure: no DOM.
- Wiring `app.js` event handlers and the CM6 update listener through
  the module's `dispatch(input)` API.
- `alignment-ticks.js` rewritten to read driver + tick Y from the
  module instead of tracking its own.
- Deletion of: `previewExpected`, `editorExpected`, `previewLockUntil`,
  `editorLockUntil`, `_syncSuspendedUntil`, the `rafSchedSync`
  multi-key scheduler, the 250 ms / 1000 ms post-render setTimeouts,
  and the `markUserScroll` plumbing in `alignment-ticks.js`.

**Non-goals.**

- Changing the v0.2.4 line-level sync semantics. The math is the same;
  it is just *coordinated* now.
- Editing the kernel render pipeline. The module subscribes to
  `renderComplete` from `app.js`; the kernel doesn't change.
- Touching the CodeMirror search extension. Search highlight already
  works on its own.
- Cross-platform behaviour. Same-platform fixes only (still WKWebView
  on macOS).

## 4. State machine

### 4.1 States

```
IDLE                  - no recent user input on either side
DRIVING_EDITOR        - editor was the most recent driver
DRIVING_PREVIEW       - preview was the most recent driver
LOCKED_PROGRAMMATIC   - we just wrote scrollY to the follower; expect
                        a matching scroll event we must absorb
SUSPENDED             - splitter drag or render-in-progress; all
                        outputs gated until release
```

### 4.2 Inputs

```
editorWheel            user's wheel/touchmove on editor scrollDOM
editorScroll(y)        editor scrollDOM scroll event
editorCursor(line)     CM6 selectionSet or docChanged
previewWheel           user's wheel/touchmove on preview window
previewScroll(y)       preview iframe contentWindow scroll event
previewClick(evt)      click inside preview body
splitterDragStart
splitterDragEnd
renderStart            applyRender about to mutate iframe DOM
renderComplete         applyRender returned, layout settled
frameTick              one rAF — used as the deferred-action driver
idleTimeout            no user input for 600 ms
```

### 4.3 Outputs (commands the module emits to adapters)

```
setPreviewScrollTop(y)
setEditorScrollTop(y)
setEditorCursor(line)
forceAlignTick(deltaY, side)   single corrective scrollBy on follower
invalidateBlockCache()
publishDriver(side)            for alignment-ticks colour state
publishTickYs({ editor, preview })
```

### 4.4 Transition table

(Subset — full table in §6.1 and tests.)

| From                | Input                  | To                      | Outputs                                     |
| ------------------- | ---------------------- | ----------------------- | ------------------------------------------- |
| IDLE                | editorWheel            | DRIVING_EDITOR          | publishDriver(editor)                       |
| IDLE                | previewWheel           | DRIVING_PREVIEW         | publishDriver(preview)                      |
| IDLE                | editorCursor(L)        | DRIVING_EDITOR          | resolve+emit setPreviewScrollTop(y)         |
| DRIVING_EDITOR      | editorScroll(y)        | LOCKED_PROGRAMMATIC     | resolve+emit setPreviewScrollTop(y)         |
| LOCKED_PROGRAMMATIC | previewScroll(y≈expY)  | DRIVING_EDITOR          | (consume, no output)                        |
| LOCKED_PROGRAMMATIC | previewScroll(y≢expY)  | DRIVING_PREVIEW         | publishDriver(preview); resolve reverse     |
| LOCKED_PROGRAMMATIC | frameTick × 2          | <prev driver>           | (timeout, drop expectation)                 |
| DRIVING_EDITOR      | idleTimeout            | IDLE                    | publishDriver(none)                         |
| any                 | splitterDragStart      | SUSPENDED               | (none)                                      |
| SUSPENDED           | splitterDragEnd        | <prev>                  | invalidateBlockCache(); resolve once        |
| any                 | renderStart            | SUSPENDED               | (none)                                      |
| SUSPENDED           | renderComplete         | <prev>                  | invalidateBlockCache(); resolve once        |
| DRIVING_*           | frameTick + drift>1px  | (same)                  | forceAlignTick(Δ, follower) — once per step |

### 4.5 Drift / force-align rule

After every output that writes the follower's scrollY, the module
schedules a `frameTick` continuation. On that tick:

- Read the follower's actual tick Y (alignment-ticks already exposes
  the math; the module computes it directly using its merged math
  primitives).
- Compute Δ = expectedTickY − actualTickY.
- If `|Δ| ≤ 1` → done.
- If `1 < |Δ| ≤ 8` and follower is **not** at end-of-doc → emit
  `forceAlignTick(Δ, follower)`. Do not retry on next tick — one-shot.
- If `|Δ| > 8` → assume layout race; skip; next driver event will
  re-resolve from scratch.

End-of-doc detection: `follower.scrollY + follower.clientHeight ≥
follower.scrollHeight − 1`.

## 5. Module API

```js
// frontend/scroll-sync.js
window.md4xScrollSync = {
  // Wiring (called once by app.js after editor + iframes are ready).
  init({ getEditor, getActiveIframe, callbacks }),

  // Inputs — adapters call these.
  editorWheel(),
  editorScroll(),
  editorCursorChanged(),
  previewWheel(iframeWindow),
  previewScroll(iframeWindow),
  previewClick(iframeWindow, evt),
  splitterDragStart(),
  splitterDragEnd(),
  renderStart(),
  renderComplete(),

  // Read-only state queries (alignment-ticks subscribes).
  state(),                          // current FSM state
  driver(),                         // 'editor' | 'preview' | null
  tickYs(),                         // { editor, preview } in viewport coords

  // Pure math — folded in from alignment-math.js, re-exported as the
  // test file currently targets `alignment-math.js`.
  math: { currentBlock, tickY, tickYClampedForCurrent,
          lineYInBlock, lineFromClickY },
};
```

Callbacks the module invokes (plumbed by `init()`):

```js
{
  setPreviewScrollTop(y),
  setEditorScrollTop(y),
  setEditorCursor(line),
  forceAlignTick(deltaY, side),
  invalidateBlockCache(),
  onDriverChange(side),
  onTickYsChange({ editor, preview }),
}
```

This keeps DOM-touching code out of the module — the module is
pure-state + pure-math. Adapters in `app.js` and `alignment-ticks.js`
do the actual reads/writes.

## 6. Test plan

Per project SDD/TDD discipline: spec → tests → code.

### 6.1 State machine tests

`frontend/tests/scroll-sync.test.mjs`. Each case is a tuple
`(initialState, [inputs], expectedFinalState, expectedOutputs)`. No
DOM.

Cases (~25):

1. IDLE + editorWheel → DRIVING_EDITOR; publishDriver(editor).
2. IDLE + previewWheel → DRIVING_PREVIEW.
3. IDLE + editorCursor → DRIVING_EDITOR; setPreviewScrollTop emitted.
4. DRIVING_EDITOR + editorScroll → LOCKED_PROGRAMMATIC; setPreviewScrollTop.
5. LOCKED_PROGRAMMATIC + previewScroll(matching expY) → DRIVING_EDITOR; no
   output.
6. LOCKED_PROGRAMMATIC + previewScroll(non-matching) → DRIVING_PREVIEW;
   reverse setEditorScrollTop emitted.
7. LOCKED_PROGRAMMATIC + 2× frameTick (no scroll event arrived) →
   prior driver state restored.
8. DRIVING_EDITOR + idleTimeout → IDLE; publishDriver(null).
9. any + splitterDragStart → SUSPENDED; outputs gated.
10. SUSPENDED + setPreviewScrollTop attempt → no emit.
11. SUSPENDED + splitterDragEnd → prior state; invalidateBlockCache; resolve once.
12. any + renderStart → SUSPENDED.
13. SUSPENDED + renderComplete → prior state; invalidateBlockCache; resolve once.
14. DRIVING_EDITOR + frameTick + drift = 0 → no force-align emitted.
15. DRIVING_EDITOR + frameTick + drift = 4 px → forceAlignTick(4, preview) emitted; one-shot.
16. DRIVING_EDITOR + frameTick + drift = 4 px + follower at end-of-doc → no
    force-align emitted.
17. DRIVING_EDITOR + frameTick + drift = 12 px → no force-align emitted (race).
18. DRIVING_EDITOR + frameTick → frameTick again → only first force-align fires.
19. previewClick(line=42) → setEditorCursor(42) emitted.
20. Resolver: editor cursor on first source line → previewY = 0 (cover page reveal).
21. Resolver: editor cursor on last source line → previewY = scrollHeight − clientHeight.
22. Resolver: cursor mid-block, sourcepos present → interpolated previewY between block top and bottom.
23. Resolver: cursor mid-block, sourcepos absent → previewY = block top (fallback).
24. invalidateBlockCache called on splitterDragEnd, renderComplete (verify single call each).
25. After invalidateBlockCache, the next resolve emits a fresh setPreviewScrollTop using rebuilt cache.

### 6.2 Math tests

The 20 tests already in `frontend/tests/alignment-math.test.mjs`
continue to pass. The merge is **export-compatible**: the test file
will import the math from the merged location with no changes (or one
minimal path change, documented in §7.4).

### 6.3 Manual / integration smoke

After wiring, verify each path on a 5k-line doc with KaTeX + mermaid:

- Type a paragraph: preview follows cursor, ticks aligned within 1 px.
- Cmd+Up/Down arrow keys: editor cursor moves one line, preview tick
  moves visibly with it.
- Click in preview: editor cursor lands at clicked source line.
- Wheel scroll editor: preview follows; release; flag stays
  `editor` for ~600 ms then goes idle.
- Wheel scroll preview: editor follows; reverse direction works
  symmetrically.
- Drag splitter: no sync runs; release; one resolve fires.
- Switch template: SUSPENDED during render; one resolve on
  renderComplete.
- ⌘F open + ⌘G next: cursor jumps to next match → resolver runs →
  preview shows match.
- Cover-page seam: cursor on line 1 → preview at top, no drift.
- End-of-doc: scroll to last line → no force-align jitter.

## 7. Implementation phases

Each phase compiles + lints + tests + ships independently. The app
remains usable at every step.

### 7.1 Phase A — write the module + tests, do not wire

1. Create `frontend/scroll-sync.js`. Implement state machine + resolver
   + math (folded from alignment-math.js).
2. Write `frontend/tests/scroll-sync.test.mjs` for all 25 cases above.
3. Existing `alignment-math.js` remains in place; re-exports from
   `scroll-sync.js` so the existing test file does not break.

`node --test` green for both test files.

### 7.2 Phase B — wire one path

Pick the simplest path to migrate first: **editor cursor → preview**.

1. `app.js`'s CM6 update listener calls
   `md4xScrollSync.editorCursorChanged()` instead of
   `rafSchedSync('editorCursor', syncPreviewFromCursor)`.
2. `init({ callbacks: { setPreviewScrollTop } })` plumbs the actual
   DOM write back to `app.js`.
3. Old `syncPreviewFromCursor` left in place for the *other* triggers
   that haven't been migrated yet.
4. Verify behaviour unchanged for typing + arrow keys.

### 7.3 Phase C — migrate remaining paths

One per commit:

- editor scroll
- preview scroll
- preview click
- splitter drag start/end
- render start/complete

After all are migrated, delete the old top-level functions and the
five module-level state variables.

### 7.4 Phase D — fold alignment-math.js + retire alignment-ticks driver state

1. Move math primitives into `scroll-sync.js`. Keep
   `alignment-math.js` as a thin re-export module that simply does
   `module.exports = require('./scroll-sync.js').math` (and the same
   for the IIFE / window-global). The existing
   `alignment-math.test.mjs` continues to pass via that re-export.
2. Once verified, the test file is updated to import from the new
   location and `alignment-math.js` is deleted.
3. `alignment-ticks.js` rewrites to read `driver()` and `tickYs()`
   from the module each frame, drops `markUserScroll` and the
   internal driver-state machine. Force-align reads from the module's
   resolver-emitted expected tick Y.

### 7.5 Phase E — strip dead code

- Delete `previewExpected`, `editorExpected`, `previewLockUntil`,
  `editorLockUntil`, `_syncSuspendedUntil`, `consumeExpectedScroll`,
  `rafSchedSync`, the post-render 250 ms/1000 ms setTimeouts.
- Verify no remaining import references.

## 8. Risks

1. **Force-align oscillation.** Mitigated by one-shot per resolver
   step and the |Δ| > 8 px race-skip. Test case 18 covers it.
2. **CM6 scrollIntoView racing the resolver.** When CM auto-scrolls
   on cursor change, both the editor scroll listener AND the cursor
   listener fire. The state machine's `LOCKED_PROGRAMMATIC` → driver
   transition handles this (the editor's reactionary scroll is
   absorbed). Test cases 4–7 cover it.
3. **Bundle size.** scroll-sync.js will be ~6–8 KB minified; net
   reduction once the scattered code is deleted.
4. **WKWebView smooth-scroll behaviour.** The module assumes one
   scroll event per programmatic write. If WKWebView fires multiple
   intermediate events for `scrollTo({behavior:'smooth'})`, the
   2-frameTick timeout in LOCKED_PROGRAMMATIC catches it. We may
   need to switch to `behavior: 'auto'` (immediate) — the user's eye
   barely notices the difference at line-level granularity.

## 9. Open questions

1. **Should idleTimeout be configurable in `settings.json`?** Default
   600 ms; cross-fade of driver colour in alignment-ticks reads it
   too. Probably no — just constant.
2. **What about Cmd+End / Cmd+Home jumps?** They fire both
   docChanged-style large delta and selectionSet. The resolver
   handles a single editorCursor input the same way; verify
   behaviour matches v0.2.4.
3. **Settings panel "scroll smoothness" toggle?** Out of scope here.

## 10. Out of scope (deferred)

- Multi-cursor / multi-selection sync — preview only paints one
  active match.
- Synchronizing horizontal scroll — preview rarely scrolls
  horizontally and the editor uses line-wrap by default.
- Cross-window sync (e.g. dual-monitor preview) — single window only.
