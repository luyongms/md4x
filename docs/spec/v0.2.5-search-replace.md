# v0.2.5 — Editor search/replace with preview highlight

**Status:** spec draft.
**Layer:** GUI only (`crates/md4x-gui/frontend/app.js`,
`crates/md4x-gui/frontend/preview-highlight.js` (new),
`crates/md4x-gui/cm6-build/`). No kernel, no plugin changes.

---

## 1. Problem

The CM6 editor in md4x has no search. ⌘F does nothing. Users editing
multi-page markdown have no way to locate, navigate, or replace text
without scrolling. Even if they bring up a panel, jumping to a hit
should also re-anchor the live preview to the same passage so the
WYSIWYG loop is preserved.

## 2. Goal

Add full search/replace to the editor and propagate the active query
to the preview as a non-destructive highlight overlay.

Bidirectional intent:

- Editor: ⌘F panel, regex / case / whole-word toggles, ⌘G next, ⇧⌘G
  prev, replace, replace all.
- Preview: each editor match that *also exists as text* in the rendered
  preview is painted as a highlight via the **CSS Custom Highlight API**.
  No DOM mutation. Active match becomes a distinct shade.
- Cursor jump on next/prev → existing line-level scroll sync
  (v0.2.4) drags preview to the matched line "for free".

## 3. Scope

**In scope.**

- `@codemirror/search` extension wired into the bundle and editor config.
- ⌘F, ⌘G, ⇧⌘G, ⌘⌥G replace, ⇧⌘⌥G replace-all keybinds — whatever the
  official `searchKeymap` exposes.
- A new module `frontend/preview-highlight.js` that:
  - Builds `Range` objects for query matches in the active iframe's
    document.
  - Registers them under a single named `Highlight` (`md4x-search`).
  - Maintains a separate `md4x-search-active` highlight for the active
    match.
  - Rebuilds on query change AND on every `applyRender`.
- CSS rules in the preview template (`templates/<x>/preview.html` and
  the runtime template injection path) for `::highlight(md4x-search)`
  and `::highlight(md4x-search-active)`.
- Counter format in the search panel footer/status:
  `i of N · M visible in preview` when `M < N`; just `i of N` when
  `M === N`.
- Inline pill above the active match's preview block, **only** when
  the active match has zero registered Ranges in preview — text:
  `match not visible in preview`.

**Non-goals.**

- Vim mode. (Defer; tracked as a settings-toggled future phase.)
- Search inside frontmatter, KaTeX-rendered glyphs, SVG `<text>`,
  `<canvas>`. Coverage is best-effort, governed by the rule in §5.
- Cross-file / multi-doc search (md4x is single-file).
- Reconciling source markdown markup (`**bold**`) with rendered text
  (`bold`). Editor matches the source verbatim; preview is text-only.
- Replace operating on the preview. Replace mutates source; preview
  re-renders downstream.

## 4. Behavior

### 4.1 Editor

- ⌘F opens the official search panel (top of editor, per `search({top:true})`).
- Regex / case-sensitive / whole-word toggles inherit upstream defaults.
- ⌘G / ⇧⌘G cycle forward / backward through all matches in the source.
- Replace and Replace-all act on the editor source. The render pipeline
  observes the document change and re-renders the preview as usual;
  preview highlights rebuild from the new source on the next applyRender.

### 4.2 Preview

- On every search-query change AND every `applyRender`, the preview
  highlight builder:
  1. Clears `md4x-search` and `md4x-search-active`.
  2. If the query is empty → done.
  3. Walks `document.body` text nodes, skipping nodes whose nearest
     ancestor element matches: `svg, canvas, .katex, .katex-display,
     [data-md4x-no-highlight]`.
  4. For each matching substring (respecting case / whole-word /
     regex flags taken from the editor's search query), constructs a
     `Range` and adds it to the `md4x-search` `Highlight`.
- The active match (current cursor selection in the editor) is painted
  with `md4x-search-active`. Mapping is by occurrence ordinal:
  the *k*-th editor match maps to the *k*-th preview Range, when one
  exists.
- If the *k*-th editor match has no corresponding preview Range,
  the active highlight is empty for that step. The pill (§4.4) fires.

### 4.3 Counts

Two integers exposed to the search panel footer:

- `N` — total editor matches (already computed by `@codemirror/search`).
- `M` — total Ranges currently in the `md4x-search` Highlight.

Format: `i of N · M visible in preview` if `M < N`, else `i of N`.

### 4.4 Not-visible pill

Single small pill, position fixed at the top of the preview pane (or
near the active block top, whichever is feasible without DOM mutation
inside the iframe content). Visible **only** when the editor's active
match has no corresponding preview Range. Text:
`match not visible in preview`. Disappears when stepping to a match
that does have a Range, or when the panel closes.

### 4.5 Feature detection

If `typeof CSS === 'undefined' || !CSS.highlights || typeof Highlight === 'undefined'`,
the preview highlight builder no-ops. Editor search still works.
Counter degrades to `i of N` (M=0). Pill never fires (the user
understands no preview painting is happening; documenting this in §7).

## 5. Architecture

### 5.1 cm6-build

Add to `package.json` deps:

- `@codemirror/search`

Re-export from `cm6-entry.mjs`:

- `search`, `searchKeymap`, `openSearchPanel`, `closeSearchPanel`,
  `getSearchQuery`, `setSearchQuery`, `SearchQuery`, `findNext`,
  `findPrevious`, `replaceNext`, `replaceAll`.

Bundle re-built into `frontend/vendor/cm6-bundle.js` via existing
esbuild script. No esbuild config change.

### 5.2 app.js wiring

- Append `search({ top: true })` to the editor extensions array.
- Append `keymap.of(searchKeymap)` to the editor extensions array
  (after existing keymaps).
- A `StateField` (or simpler: an `EditorView.updateListener`) watches
  `getSearchQuery(state)` and the active match position; on change,
  calls into `previewHighlight.update(query, activeOrdinal)`.
- On `applyRender` completion, calls
  `previewHighlight.rebuildFromActiveQuery()`.

### 5.3 preview-highlight.js (new)

Public API:

```
window.md4xPreviewHighlight = {
  update(query, activeOrdinal),    // re-walk text, rebuild highlights
  rebuildFromActiveQuery(),         // re-run with last-seen query
  clear(),                          // no query / panel closed
  countVisible(),                   // returns M
  hasRangeForOrdinal(k),            // returns bool, drives pill
};
```

Internal:

- One `Highlight` registered as `md4x-search` (all matches).
- One `Highlight` registered as `md4x-search-active` (single Range).
- `currentRanges: Range[]` retained so we can flip the active one
  without re-walking.
- `currentQuery` retained for `rebuildFromActiveQuery`.

Walker:

- Single `TreeWalker(NodeFilter.SHOW_TEXT)` over the active iframe
  body. Reject filter checks ancestor against the skip-set
  (`svg, canvas, .katex, .katex-display, [data-md4x-no-highlight]`).
- For each accepted text node, find query matches per the flags. If
  regex, compile once outside the loop; reset `lastIndex` per node.
- Each match → `Range` with `setStart(node, i)` /
  `setEnd(node, i+len)`. Push to `currentRanges`, register in
  `md4x-search` highlight.

### 5.4 CSS

Inject into the preview template (or via a constant CSS string that
the runtime appends to the iframe `<head>`):

```css
::highlight(md4x-search)        { background-color: #fff48a; color: inherit; }
::highlight(md4x-search-active) { background-color: #ffb547; color: inherit; }
```

### 5.5 Pill

A single absolutely-positioned `<div>` *outside* the iframe (in the
host preview pane), so we don't mutate iframe content. Visible class
toggled from `app.js` based on `hasRangeForOrdinal`.

## 6. Test plan

Per project SDD/TDD discipline: failing tests before code.

### 6.1 alignment-math.js style pure-fn tests

New file: `crates/md4x-gui/frontend/tests/preview-highlight.spec.js`.
Pure logic only — does **not** require a real iframe; uses `jsdom`
for the text-walker tests via the existing test runner.

Cases:

1. **Empty query → no Ranges, M=0, no pill.**
2. **Query "foo" in plain prose → 1 Range, M=1.**
3. **Query "foo" with one occurrence inside `<svg><text>foo</text></svg>`
   → 0 Ranges, M=0.**
4. **Query "foo" with one occurrence inside `.katex` subtree → 0
   Ranges.**
5. **Query "foo" appearing 3× — twice in prose, once in `<svg>`
   → M=2, N=3 (N comes from editor, simulated).**
6. **Case-sensitive flag: query "Foo" matches "Foo" only, not
   "foo".**
7. **Whole-word flag: query "foo" matches "foo" but not "foobar".**
8. **Regex flag: query `/f.o/` matches "foo" and "fxo".**
9. **`hasRangeForOrdinal(k)` → true when *k*-th editor match has a
   preview Range, false otherwise.** (Mapping by ordinal.)
10. **Feature detect: when `CSS.highlights` is undefined, `update()`
    is a no-op and `countVisible()` returns 0.**

### 6.2 Integration smoke (manual, dogfood-via-PDF or live app)

- ⌘F panel opens.
- Type query → editor matches highlight, preview matches highlight.
- ⌘G cycles; preview scroll follows via existing line-sync; active
  shade flips.
- Match in mermaid block → editor lands on it, preview pill appears.
- Replace one → match count drops, preview rebuilds clean.
- Replace all → editor + preview cleared.
- Close panel (Esc) → all highlights and pill disappear.

## 7. Open questions

1. **Pill positioning.** Top-of-preview-pane (host-level overlay) is
   simplest and survives iframe re-mounts. Acceptable?
2. **Case/whole-word/regex source of truth.** `getSearchQuery(state)`
   exposes flags directly. Confirm we copy them verbatim into the
   preview walker; no separate UI.
3. **Replace inside non-paintable matches.** Replace acts on source;
   preview rebuilds from source. No special handling needed. Confirm
   no edge case around ordinal drift between flag-toggle and the
   next render frame.
4. **Color tokens.** `#fff48a` / `#ffb547` — fine to hard-code, or
   pull from `--md4x-*` tokens? (Tokens preferred; check existing
   palette for a search-yellow.)

## 8. Out of scope (deferred)

- Vim mode (`@replit/codemirror-vim`) — separate phase, behind a
  settings toggle.
- Multi-cursor selection from "select all matches" — built-in to CM6,
  enable later if requested.
- Find-in-preview-only (search the rendered text directly, ignoring
  source). Not requested; would invert the model.
