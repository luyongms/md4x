# v0.2.0 workspace restructure (draft)

## Goal

Make room for a Tauri GUI shell without disturbing the CLI shell or the
library. Convert the single-crate repo into a Cargo workspace with three
members:

- `crates/md4x-core` — the kernel + plugins + templates (was `src/`)
- `crates/md4x-cli` — the CLI shell (was `src/cli.rs` + `src/main.rs`)
- `crates/md4x-gui` — the Tauri shell (new in v0.2.0)

Rationale (recap):
- A *shell* is a layer, not the layer. The CLI is one driver of the
  kernel; the GUI is another. Both depend on `md4x-core` for everything
  except their own UX.
- Rust code stops growing toward "one crate, ten modules"; structure now
  reflects the architecture diagram (kernel + plugins + shell).
- The dist story bifurcates cleanly: `dist.sh` continues to ship the
  CLI; future `dist-gui.sh` ships the Tauri app bundle. They share the
  core but the artifacts are different.

    md4x_core::templates::available()
        .iter()
        .map(|s| s.to_string())
        .collect()

#[tauri::command]
fn render_html(md: String, template: String) -> Result<String, String> {

    Ok(format!("<style>{css}</style>{body}"))

## Code moves (mechanical part of the migration)

```
src/cli.rs                  → crates/md4x-cli/src/cli.rs
src/main.rs                 → crates/md4x-cli/src/main.rs
src/lib.rs                  → crates/md4x-core/src/lib.rs
src/render.rs               → crates/md4x-core/src/render.rs   (later: split into render/cover/chrome)
src/templates.rs            → crates/md4x-core/src/templates.rs
src/plugins/                → crates/md4x-core/src/plugins/
mermaid.min.js              → crates/md4x-core/mermaid.min.js
katex/                      → crates/md4x-core/katex/
tests/                      → crates/md4x-core/tests/   (most stay here; CLI tests stay with CLI)
tests/cli.rs                → crates/md4x-cli/tests/cli.rs
```

API breakage to expect:
- External imports change: `md4x::render::...` → `md4x_core::render::...`
  Inside the CLI shell, that's a one-line change. No external consumers
  exist yet, so this is free.
- `Cargo.lock` is regenerated; tests stay green.

## Migration plan (when you say "go")

1. **Snapshot.** Tag `v0.2.0-pre-restructure` in case of regrets.
2. **Create workspace skeleton.** Move files in five `git mv` batches
   (core lib, core assets, core plugins, CLI shell, GUI skeleton).
3. **Fix paths.** `Cargo.toml` per-crate; lib re-exports as needed;
   `include_bytes!`/`include_dir!` paths stay correct because the assets
   move with the crate.
4. **Run tests.** `cargo test --workspace` should pass with no
   behavioral change.
5. **Run dist.** `scripts/dist.sh arm64` should still build a working
   tarball (with `--features bundle-templates` plumbed through to the
   core crate).
6. **Commit as one big restructure.** No GUI code yet.
7. **Branch is now ready** for actual GUI work in subsequent commits.

## What stays the same

- Plugin trait surface and the three plugins.
- Templates layout and `templates::style_css` / `templates::cover_html`.
- `bundle-templates` feature behavior.
- `scripts/dist.sh` (paths inside it shift slightly).
- `corpus/render-all.sh` (uses the CLI binary).
- All tests pass at the same numbers (44/46/whatever) and same names.

## What's deferred to later v0.2.x

- Splitting `render.rs` into `render`/`cover`/`chrome` (architecture
  weakness #1 from the critique). Mechanical, can land in its own commit
  after the workspace move settles.
- The `PageRenderer` trait (architecture weakness #3). Wait until a
  second renderer (paged.js) is actually wanted.
- Full GUI implementation — Tauri scaffold + commands first, real UI
  in subsequent commits.
