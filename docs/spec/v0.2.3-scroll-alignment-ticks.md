# v0.2.3 — Scroll Alignment Ticks

**Status:** spec → tests → code (SDD/TDD).
**Scope:** GUI only (`crates/md4x-gui`). No kernel changes.

---

## 1. Problem

In split editor↔preview, the human eye cannot quickly verify whether the
two panes are showing **the same logical block** at corresponding
positions. Existing block-aligned scroll sync (v0.2.2) sometimes drifts
during smooth-scroll lockout, template swap, or after async render. The
user has no visual signal of drift — they must guess by reading both
sides.

## 2. Goal

Provide a **dual-strip tick system** that:

1. Continuously shows where every block boundary is, on both panes.
2. Highlights the **currently top-of-viewport block** on each pane,
   independently computed.
3. When the two highlighted ticks land at the same Y across the splitter,
   alignment is proven; when they don't, drift is visible.
4. Auto-corrects drift by scrolling the **follower** pane to match the
   **driver** pane, on scroll settle.

## 3. Non-goals (v0.2.3)

- No editor cursor-line tracking (the v0.2.2 cursor-sync is unchanged).
- No connector lines, alternating tints, hover bubbles.
- No iframe DOM mutation for tick rendering.
- No CodeMirror gutter extension.
- No kernel `Plugin` changes.

## 4. UX contract

### 4.1 Tick strip placement

| Pane    | Strip location                                   | Width                    |
|---------|--------------------------------------------------|--------------------------|
| Editor  | Overlay on right edge of CodeMirror viewport     | 14 px (fixed)            |
| Preview | Overlay on left edge of preview iframe (= template body padding gutter) | min(template padding-left, 24 px), clamp ≥ 10 px |

Both overlays:
- Live in the **main window DOM** (no iframe DOM mutation).
- `position: absolute`.
- `pointer-events: none` (do not block scroll/click in panes).
- Hug the **splitter-facing** edge of their pane.

### 4.2 Tick rendering

Per visible block, draw a faint horizontal mark in the strip:

| Block kind                 | Tick length | Tick weight | Tick color (default) |
|----------------------------|-------------|-------------|----------------------|
| Heading (H1–H6)            | 12 px       | 2 px        | `#555` 70 % opacity  |
| Other top-level block      |  6 px       | 1.2 px      | `#888` 50 % opacity  |
| **Current** (any kind)     | 10 px       | 3 px        | `#e63946` 100 %      |

- "Top-level block" = paragraph, list, blockquote, code block, math
  block, admonition, table.
- Current tick is rendered on the **splitter-facing half** of its strip:
  - Editor strip: tick spans `[stripRight − tickLen, stripRight]`.
  - Preview strip: tick spans `[stripLeft, stripLeft + tickLen]`.
- Non-current ticks are centered in the strip.

### 4.3 "Current" block definition (per pane, independent)

```
currentBlock(pane) = last block B in pane such that B.top ≤ pane.scrollTop
```

If no block satisfies (viewport above first block), `currentBlock = first
block`.

### 4.4 Tick Y position

For each block whose tick is in the visible strip:

```
tickY = block.top − pane.scrollTop
```

Clamp into strip bounds `[0, stripHeight]` for rendering. **Current tick
Y is not clamped** — if `currentBlock.top` is above viewport (we're
scrolled mid-block), current tick is rendered at `Y = 0` (top of strip).
Both panes clamp identically when aligned, so diagnostic value
preserved.

### 4.5 Auto-correction on drift

After driver pane stops scrolling (≥ 50 ms idle), evaluate alignment:

```
ordinalDriver  = ordinal of currentBlock(driver)
ordinalFollow  = ordinal of currentBlock(follower)

subOffsetDriver  = driver.scrollTop  − currentBlock(driver).top
subOffsetFollow  = follower.scrollTop − currentBlock(follower).top
```

Drift exists if **either**:

- `ordinalDriver ≠ ordinalFollow`, **or**
- Same ordinal but `|subOffsetDriver − subOffsetFollow| > 4 px`.

On drift, programmatically smooth-scroll follower to:

```
followerTarget = blockInFollower[ordinalDriver].top + subOffsetDriver
```

Correction is suspended during:
- Splitter drag (existing `suspendSync`).
- Template swap (existing).
- Active smooth-scroll lockout (300 ms per v0.2.2).
- The 200 ms window immediately after a correction fires (re-entrancy
  guard).

### 4.6 Driver detection

`driver: 'editor' | 'preview' | 'idle'`

| Event                                              | New driver |
|----------------------------------------------------|------------|
| `wheel` / `touchmove` on a pane                    | that pane  |
| Scrollbar drag start on a pane (`mousedown` + drag)| that pane  |
| `keydown` arrow/page on focused pane               | that pane  |
| Cursor change in editor (no scroll)                | editor (fallback only) |
| 600 ms with none of the above                      | idle       |

**Programmatic scrolls do NOT update driver.** Marker flag
`isProgrammaticScroll` set during correction; cleared 50 ms after target
reached.

When `driver = idle`, no auto-correct fires.

### 4.7 Splitter drag

During splitter drag, hide both red current ticks (faint block ticks
remain). Resume on drag-end.

### 4.8 Color theme

Light theme:
- Faint ticks: `#888` / `#555` (above table)
- Current: `#e63946`

Dark theme:
- Faint ticks: `#aaa` 50 %
- Current: `#ff6b78`

Detect theme via existing CSS variable used by templates.

## 5. Architecture

### 5.1 Module layout

New file: `crates/md4x-gui/frontend/alignment-ticks.js`.

Public surface:

```js
export function initAlignmentTicks({
  editorContainer,   // HTMLElement wrapping CodeMirror
  previewContainer,  // HTMLElement wrapping iframe
  cmView,            // CodeMirror EditorView
  getBlockMap,       // () => { editor: BlockMap, preview: BlockMap }
  suspendSync,       // existing API from sync module
});

export function destroyAlignmentTicks();
```

`BlockMap` (already produced by v0.2.2 sync, reuse):

```ts
interface Block {
  ordinal: number;       // 0..N-1, shared across editor & preview
  top: number;           // px from pane top
  bottom: number;        // px from pane top
  kind: 'heading' | 'paragraph' | 'list' | 'blockquote' | 'code'
       | 'math' | 'admonition' | 'table';
}

interface BlockMap {
  blocks: Block[];
  scrollHeight: number;
}
```

If existing sync produces a different shape, add an adapter — do not
fork the source-of-truth.

### 5.2 Render loop

Single RAF loop owned by `alignment-ticks.js`. Subscribes to:
- `editor.scroll` event (CodeMirror `EditorView.updateListener`)
- `preview.scroll` event (iframe scroll, see § 5.3)
- `resize`
- Template swap callback

Each tick (≤ 60 fps):

1. Read `scrollTop` from each pane.
2. Resolve `currentBlock` per pane.
3. Compute tick Y for visible blocks (cull off-strip).
4. Patch DOM (set `style.transform: translateY(...)` on cached tick
   elements, no re-create).

Tick elements pre-created on first paint, reused. Pool size = max
visible blocks at any zoom.

### 5.3 Iframe geometry plumbing

Probe order:

1. Try `iframe.contentDocument` directly (same-origin fast path).
2. If `null`/SecurityError → inject content script via existing
   `md4x://` injection (already used by Tauri setup closure for drag
   feedback). Content script posts:
   ```
   { type: 'md4x:alignment-geom',
     scrollTop: number,
     blocks: Block[],          // from existing block-map plugin
     scrollHeight: number }
   ```
   on RAF-coalesced scroll, plus on resize and template swap.

Main window listens for `message` events from iframe, caches latest
geometry.

### 5.4 Auto-correct dispatcher

```js
function tryAutoCorrect() {
  if (driver === 'idle') return;
  if (suspendSync.isActive()) return;
  if (smoothScrollLockout.active) return;
  if (correctionGuard.active) return;

  const drift = computeDrift(driver);
  if (!drift) return;

  correctionGuard.start(200);
  isProgrammaticScroll = true;
  followerPane.scrollTo({ top: drift.target, behavior: 'smooth' });
  // isProgrammaticScroll cleared 50 ms after target reached
}
```

Called on debounced (50 ms) `scroll-end` event of driver pane.

### 6.3 Manual smoke checklist (visual)

1. Open a long markdown file with mixed block kinds.
2. Scroll editor by wheel — confirm preview ticks move; red ticks remain
   aligned across splitter (within 4 px).
3. Scroll preview by wheel — same in reverse.
4. Open file with deep math/mermaid that takes longer to render —
   confirm post-render tick alignment recomputes.
5. Drag splitter — red ticks hide; faint ticks remain.
6. Switch template — ticks rebuild with new template gutter width.
7. Quickly scroll wheel then release — confirm corrective nudge on
   settle, no oscillation.
8. Edit markdown to insert / delete a block — confirm tick count and
   ordinal alignment update.

## 7. Caveats & known risks

1. **Same-origin probe outcome unknown.** Cross-origin path adds
   ~30 lines content-script plumbing. Implement same-origin first; fall
   back if `SecurityError` thrown.
2. **Existing sync's BlockMap shape may differ.** Audit
   `frontend/app.js` block-sync code first; adapt or extend rather than
   duplicate.
3. **Templates with no left padding** (full-bleed designs). Fall back to
   minimum 10 px strip rendered outside iframe edge in main DOM.
4. **CodeMirror right-edge "..." indicators** (overflow markers). Strip
   sits on top with `pointer-events: none`; verify visually that dots
   remain readable through faint ticks.
5. **Auto-correct vs user trust.** If correction fires aggressively,
   user perceives "jumpy" preview. Mitigation: 50 ms settle delay +
   200 ms re-entrancy guard + suppress during smooth-scroll lockout.
6. **WKWebView ghost-iframe issue** (resolved in v0.2.2 via
   `nudgeSplitterWidth`). Tick overlay must not interfere with the
   active/inactive iframe z-stack.
7. **Driver detection edge:** keyboard-driven scroll in CodeMirror via
   arrow keys (line down). May not fire `wheel`. Listen for
   `EditorView.updateListener` with `update.geometryChanged`.
8. **Correction loop risk** if both panes oscillate near a threshold.
   Mitigation: re-entrancy guard.

## 10. Audit findings (post § 8 step 1)

Reusable primitives in `frontend/app.js`:

- Editor blocks: `getLezerBlocks()` → `[{from, to, kind}]`. `kind` is a
  lezer node name. Headings: `ATXHeading{1-6}` or `SetextHeading{1,2}`.
- Preview blocks + tops: `getPreviewBlocksCached(iframe)` returns
  `{ blocks: [{el, kind}], tops: number[] }`. Headings: `kind` is `H1`–`H6`.
- Index lookups: `lezerBlockIndexAtPos`, `previewBlockIndexAtScroll`
  (binary search).
- Coords: `editorBlockYInViewport`, `elDocTop`.
- Clamps: `clampEditorY`, `clampPreviewY`.
- Sync state: `editorExpected`, `previewExpected`, `editorLockUntil`,
  `previewLockUntil`, `consumeExpectedScroll(side, pos)`,
  `SMOOTH_LOCKOUT_MS` (300), `SCROLL_TOLERANCE_PX` (6).
- Suspend: `suspendSync(ms)`, `isSyncSuspended()`.
- RAF coalesce: `rafSchedSync(key, fn)` with keys
  `editorScroll | editorCursor | preview`.

**Same-origin confirmed.** Existing code at `app.js:441` reads
`iframe.contentWindow.document.body` without try/catch protection —
md4x:// scheme grants same-origin access in Tauri. The cross-origin
fallback path in spec § 5.3 is **not needed** for v0.2.3.

**Driver state extension.** Add `lastUserScrollSource: 'editor' |
'preview' | null` next to existing `*Expected` vars. Set on real `wheel`
/ `touchmove` / `keydown`-while-pane-focused; left null by programmatic
scrolls (which set `*Expected` instead). Decay to `null` after 600 ms of
no user-scroll events.

**Tick rendering integration points.**

- Strip DOM elements injected into existing pane containers; use a new
  RAF key `alignmentTicks` so they don't fight the three sync keys.
- Invalidate ticks alongside `invalidatePreviewBlocksCache()`.
- Hook into existing splitter-drag `suspendSync` to hide red ticks.
